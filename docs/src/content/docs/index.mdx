Keep persistent Chromium sessions on your Mac and access them from MCP, the
CLI, a local API, or the typed Rust client.

## Start with one command

The bundled `rel` CLI is the quickest way to capture a rendered page and the best place to learn Rel’s model.

```sh
rel capture https://example.com --output ./example.html
```

Rel keeps Chromium inside the installed macOS app. The CLI asks the local agent to use that browser, waits for the rendered result, and writes the HTML to disk.

## Supported runtime

Production clients use the installed `/Applications/REL.app`, which owns bundle ID `me.rel.REL`, stores current data under `~/Library/Application Support/REL`, and supervises its bundled local agent on port `17319`. CLI, SDK, and MCP adapter calls connect to that agent; the agent routes browser work back into the visible app.

Source development uses an isolated worktree-local `dist/RELDebug.app` with bundle ID `me.rel.RELDebug`, data under `~/Library/Application Support/RELDebug`, and agent port `27319`. RELDebug has separate browser-proxy ports, preferences, and Keychain namespace, so it can run alongside the installed app without replacing it. Set `REL_AGENT_PORT=27319` only when intentionally pointing a development client at RELDebug.

The embedded CEF runtime stores its OSCrypt secret in macOS Keychain as `REL Safe Storage` under account `REL`.
